# Grid Movement

Implements tile-based movement on a discrete grid: the player moves one cell at a time with a smooth tween animation, and cannot enter wall cells.

## Purpose

Grid-based games (roguelikes, puzzle games, strategy games, Sokoban-style mechanics) require movement logic that operates in integer coordinates, not continuous float positions. This demo shows how to maintain a grid position as a `Vector2i`, map it to world pixels, check a wall dictionary, and use Tween to animate the snap smoothly.

## Controls

- **Arrow keys**: Move one cell at a time
- Walls block movement; borders are impassable

## How It Works

### Node Tree

```
Main (Node2D)               ← main.gd  (wall data, grid math, visual)
└── Player (Node2D)         ← player.gd  (input, movement logic)
```

### `scripts/main.gd` — The Grid

Constants:
```gdscript
const CELL  := 40   # pixels per cell
const COLS  := 16
const ROWS  := 12
```

`wall_set: Dictionary` maps `Vector2i` cell coordinates to `true`. Checking membership is O(1) by hash:

```gdscript
func is_wall(cell: Vector2i) -> bool:
    return wall_set.has(cell)
```

`cell_to_world(cell: Vector2i) -> Vector2` converts a grid coordinate to the world pixel at the cell's center:
```gdscript
return Vector2(cell.x * CELL + CELL * 0.5, cell.y * CELL + CELL * 0.5)
```

`_ready()` populates `wall_set` by:
1. Looping all border cells (column 0, column 15, row 0, row 11)
2. Adding a hardcoded list of interior wall positions

`_draw()` renders faint grid lines and fills wall cells with a grey rectangle.

### `scripts/player.gd` — Grid Navigation

```gdscript
var grid_pos := Vector2i(2, 6)  # integer cell coordinate

func _unhandled_input(event: InputEvent) -> void:
    if not event.is_pressed() or event.is_echo():
        return
    var dir := Vector2i.ZERO
    if event.is_action("ui_up"): dir = Vector2i(0, -1)
    # ... other directions
    var next := grid_pos + dir
    if not main.is_wall(next):
        grid_pos = next
        var tween := create_tween()
        tween.tween_property(self, "position", main.cell_to_world(grid_pos), 0.1)
```

Key points:
- `event.is_echo()` — Returns true for held-key repeat events. Filtering these out gives one-tap movement only.
- The tween animates `position` (world pixels) from the current location to the new cell center over 0.1 seconds.
- `grid_pos` updates immediately; the visual (`position`) catches up via the tween.

## Grid System Theory

### Discrete vs Continuous Movement

In continuous movement, position is a float updated every frame. In grid movement, the **logical position** is an integer cell coordinate. The **visual position** (pixels on screen) can still be smooth — the tween provides that. This separation is fundamental: the gameplay logic (collision, enemies, items) operates on integer cells, while the renderer shows smooth transitions.

### Vector2i for Grid Coordinates

`Vector2i` is an integer vector. Using integers for grid coordinates prevents floating-point drift when summing directions over many moves. `Vector2(2.0, 3.0) + Vector2(0.3, 0.0)` repeated 10 times gives `Vector2(5.0, 3.0)` with possible rounding error; `Vector2i(2, 3) + Vector2i(1, 0)` is always exact.

### Dictionary Wall Set

A `Dictionary` with `Vector2i` keys gives O(1) lookup:
```gdscript
wall_set[Vector2i(4, 2)] = true
wall_set.has(Vector2i(4, 2))  # → true
wall_set.has(Vector2i(5, 5))  # → false
```

Alternatives (checking a 2D array, iterating a list) are O(1) and O(n) respectively. The Dictionary approach scales to sparse, large, or procedurally generated maps.

### Input Echo Filtering

```gdscript
if not event.is_pressed() or event.is_echo():
    return
```

`is_echo()` is true for key-repeat events generated by the OS when a key is held. Filtering these gives strict one-press-one-step behavior. If you want held-key movement (the player continues moving while holding), you would instead poll `Input.is_action_pressed()` in `_process()` with its own timer.

### Tween for Visual Smoothness

The tween animates `self.position` (the Node2D's world position) from the current pixel to the target cell center. The grid logic (`grid_pos`) is already updated before the tween starts — the tween is purely cosmetic. This means the player's logical position is always accurate even if two tweens overlap.

## Key Godot APIs

| API | Purpose |
|-----|---------|
| `Vector2i(x, y)` | Integer 2D vector for grid coordinates |
| `Dictionary.has(key)` | O(1) membership test |
| `InputEvent.is_echo()` | True for OS key-repeat events |
| `InputEvent.is_pressed()` | True on initial press |
| `create_tween().tween_property(node, prop, value, time)` | Animate a property |
| `Node2D.position` | World pixel position |
