# Concept tags

Which demos share a property, cut across the categories in the root
[README](../README.md). Generated by `tools/build_tags.py` from the demos'
own source, so a demo that stops using audio stops being tagged `audio`
without anyone remembering.

The one hand-picked tag is `good-first-demo`: what to read first is a
judgement, not something the code can answer.

## The tags

| Tag | Demos | What it means |
|-----|-------|---------------|
| `physics` | 59 | Bodies, areas and collision — the engine moving things for you. |
| `shader` | 9 | Carries a shader, whether written in a file or built in code. |
| `audio` | 8 | Makes a sound, or routes one. |
| `ui` | 90 | Built out of Control nodes rather than drawing. |
| `procedural` | 26 | Generates its own content rather than loading it. |
| `persistence` | 5 | Reads or writes something that outlives the run. |
| `signals` | 26 | Declares a signal of its own — the loose-coupling lesson. |
| `component` | 42 | Ships a class_name you can lift into another project. |
| `tool-script` | 2 | Runs inside the editor as well as the game. |
| `shows-its-working` | 44 | Draws the state it is explaining, not just the result. |
| `needs-gamepad` | 1 | Wants a controller plugged in to show its subject. |
| `needs-network` | 2 | Talks to something outside the machine. |
| `good-first-demo` | 7 | Short, self-contained, and assumes nothing. |
